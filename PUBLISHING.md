# Publishing on crates.io

Vitesse is published on [crates.io](https://crates.io/crates/vitesse) as the `vitesse`
crate, under its [proprietary license](LICENSE): the source is visible there so that it can
be audited and built, and anyone may depend on it.

## One release = one push

1. Bump `version` in [`Cargo.toml`](Cargo.toml) and write its section in
   [`CHANGELOG.md`](CHANGELOG.md) (`## [X.Y.Z] - …`).
2. Commit and push to `master`.

Once CI is green, the [`release.yml`](.github/workflows/release.yml) workflow sees that the
version has no tag yet: it creates the tag `vX.Y.Z` (the same version with a `v` in front)
and its GitHub release, with that version's section of `CHANGELOG.md` as notes (or notes
generated by GitHub when there is no section), runs the tests and publishes the crate. There
is no form to fill in, and nothing is installed locally: it works from the GitHub website on
a phone. A push that keeps the same version releases nothing.

A release drafted by hand (**Releases → Draft a new release**, tag `vX.Y.Z`, **Publish
release**) still publishes too, after checking that the tag matches the version. From the
**Actions** tab the workflow can also be started by hand, as a dry run by default (the
package is built and checked, nothing is uploaded).

## One-time setup

- A crates.io account with a verified e-mail address.
- A token from [crates.io/settings/tokens](https://crates.io/settings/tokens) with the scopes
  **publish-new** and **publish-update**, saved as the repository secret
  `CARGO_REGISTRY_TOKEN` (GitHub → Settings → Secrets and variables → Actions).

Without this secret, the automatic release still creates the tag and the GitHub release, and
only the publication on crates.io is postponed: add the secret, then run the workflow by hand
from the **Actions** tab with **Only check the package** unticked.

## From a computer

```sh
cargo login                 # paste the token, once
cargo publish --dry-run     # packages and builds exactly what would be uploaded
cargo publish
```

## The ecosystem, in order

The five projects by Maxime Nathan Lestage depend on each other through crates.io, so they
are published in this order, each one after the previous one is online:

1. **Active** — `active`
2. **Vitesse** — `vitesse` (this repository)
3. **Securite** — `securite`
4. **Memoire** — `memoire-orm-derive`, then `memoire-orm`
5. **Paquets** — `paquets-macros`, then `paquets` (depends on the four above)
